# Completeness inventory

This is a hand written list of every canonical feature that the project's
shared agent instructions require of a user facing application. It exists so
that a missing feature reads as a missing row, not as a silent gap. A row is
added when a feature is added, and its status is corrected the moment its
implementation changes; nothing here is generated from source.

`buildscripts/checks/completeness_guard.py` reads this table at configure
time. It carries its own hard coded list of the canonical feature names and
fails when one of them has no row, when a row names an implementation file,
documentation article, test file or capture path that does not exist on
disk, or when a row claims localized coverage that
`share/locale/audacity_yue_HK.ts` does not actually carry. A row whose status
is `missing` or `not applicable` must give its reason in the Notes column;
those rows are reported by the guard but do not fail it, because the guard's
job today is to keep the list honest, not to pretend every feature already
exists.

## How to read the table

- **Implementation** lists the real source files that carry the feature.
  Empty means nothing has been written yet.
- **Documentation** is the feature article under `docs/features/`.
- **Localized copy** is the translation context inside
  `share/locale/audacity_yue_HK.ts` that carries this feature's user facing
  strings, when the feature has any.
- **Persistence** is the settings key or file path the feature's state lives
  under, when it has state.
- **Test** is the focused test file that exercises the feature's logic.
- **Capture** is a path under `docs/design/captures/` or `docs/site/captures/`
  that shows the feature rendered in the built application. Most rows do not
  have one yet; a missing capture is recorded plainly rather than invented.
- **Status** is one of `implemented`, `partial`, `not applicable`, or
  `missing`.
